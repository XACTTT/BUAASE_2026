# 资源检测与人工审核 - 业务逻辑全链路分析

## 一、系统概述

### 四种材料类型

| 材料类型 | detect_type | task_type | 说明 |
|---------|------------|-----------|------|
| 图像 | image | image | 单独图像伪造检测(ELA/噪声/EXIF等) |
| 论文文本 | paper | paper_text | 论文AIGC检测(BERT+LLM) |
| 审稿文本 | review | review_text | 审稿文本模板化/AIGC检测 |
| 综合检测 | multi | multi_material | 多材料交叉验证(图像+论文+审稿) |

### 三种用户角色

| 角色 | 权限位(4位) | 说明 |
|-----|------------|------|
| Admin(管理端) | - | 系统管理、组织审批、审核申请审批 |
| Publisher(提交者) | upload/submit/publish | 上传材料、提交检测、创建审核申请 |
| Reviewer(审核者) | review | 执行具体人工审核任务 |

## 二、资源检测业务链路

### 2.1 检测提交流程

```
[Publisher] 上传文件 → 文件解析(提取图像+文本) → 创建ResourceContainer
     → 提交检测(DetectionTask) → Celery异步处理 → AI检测 → 结果存储
```

**关键文件:**
- 后端入口: `core/views/views_dectection.py`
  - `submit_detection2()` → 图像/综合检测 (Celery `ai` 队列)
  - `submit_text_detection()` → 文本检测
  - `_submit_structured_detection()` → 论文/审稿/综合检测 (Celery `cpu` 队列)
- Celery任务: `core/tasks_new.py`
  - `fetch_batch` → GPU图像检测
  - `run_structured_detection_task` → 结构化文本检测
- AI服务: `AI_service/service_code/`
  - 图像检测: `pipeline/pipeline_single_image.py`
  - 文本检测: `service_runtime/bert_text_handler.py`
- 前端页面: `前端用户端/src/pages/step/[id].vue` (调度)
  - image → `components/steps/DetectionReviewStep.vue`
  - paper_text/review_text → `components/steps/TextDetectionResultView.vue`
  - multi_material → `components/steps/MultiMaterialResultView.vue`

### 2.2 各材料类型检测指标

#### 图像检测(image) - 7维度
| 维度 | 中文名 | 说明 |
|------|--------|------|
| method1 | 高斯模糊 | 检测高斯模糊伪造痕迹 |
| method2 | 亮度/对比度调节 | 检测亮度对比度异常 |
| method3 | 智能修复 | 检测inpainting修复痕迹 |
| method4 | 暴力覆盖 | 检测暴力覆盖篡改 |
| method5 | 同图复制 | 检测同图内区域复制 |
| method6 | 重叠切割 | 检测重叠切割拼接 |
| method7 | 跨图拼接 | 检测跨图拼接伪造 |

结果模型: `DetectionResult`(整体) + `SubDetectionResult`(每维度概率+mask图)

#### 论文文本检测(paper_text)
- BERT分类: 每段落AIGC概率(ai_probability)
- LLM分析: 事实性造假分析(factual_fake_reason)
- 维度评分: aigc_generation(生成概率)、template_tendency(模板倾向)、consistency(一致性)

结果模型: `TextDetectionResult` + `StructuredDetectionResult`

#### 审稿文本检测(review_text)
- BERT分类: 每段落AIGC概率
- 模板化分析: template_tendency_score(0-1) + template_analysis_reason
- 维度评分: 同论文，侧重模板化倾向

结果模型: `TextDetectionResult` + `StructuredDetectionResult`

#### 综合检测(multi_material)
- 图像检测: 同image的7维度
- 论文文本: 同paper_text的段落分析
- 审稿文本: 同review_text的模板分析
- 交叉验证: 材料间一致性检查

结果模型: 全部三种模型的组合

## 三、人工审核业务链路(三个阶段)

### 3.1 阶段一: 人工审核申请

**业务流程:**
```
[Publisher] 检测历史页面 → 查看检测结果 → 选择材料 → 选择审核员 → 提交审核申请
```

**页面:** 前端用户端 `pages/history.vue` → `pages/step/[id].vue`

**后端API:** `POST /create_review_task_with_admin_check/`
- 请求参数: `task_id`(或`image_ids`+`text_ids`), `reviewer_ids`, `check_reason`
- 自动解析: 根据task_id从DetectionTask中提取关联的image_ids和text_ids
- 创建: ReviewRequest(status1=pending, status2=pending)
- 关联: imgs M2M, text_resources M2M, reviewers M2M
- 通知: 发邮件给组织管理员

**前端组件差异:**
| 材料类型 | 组件 | 提交payload |
|---------|------|------------|
| image | DetectionReviewStep.vue | `{image_ids, reviewers}` |
| paper_text | TextDetectionResultView.vue | `{task_id, reviewers, reason}` |
| review_text | TextDetectionResultView.vue | `{task_id, reviewers, reason}` |
| multi_material | MultiMaterialResultView.vue | `{task_id, reviewers, reason}` |

**已知问题:**
- image类型提交payload缺少reason字段
- image使用image_ids而非task_id，与其他类型不一致
- paper_text和review_text使用相同组件，无法区分

### 3.2 阶段二: 人工审核申请审批

**业务流程:**
```
[Admin] 管理端审核管理页面 → 查看申请列表 → 点击操作按钮 → 审核详情弹窗 → 通过/拒绝
```

**页面:** 前端管理端 `pages/reviews.vue`

**后端API:**
- `GET /admin/review-requests/` → 获取审核申请列表
- `GET /admin/review-requests/<id>/` → 获取审核申请详情
- `POST /admin/review-requests/<id>/handle/` → 通过/拒绝

**审批通过时(handle_review_request, choice=1):**
1. 设置 status2='accepted'
2. 为每个审核员创建 ManualReview(status=undo)
3. 为每张图像创建 ImageReview(result=False)
4. 为每条文本创建 TextReview(result=None)
5. 发送P2R通知给审核员

**已知问题:**
- reviews.vue内联渲染检测结果，未复用detection组件
- 审批详情弹窗中multi_material类型重复渲染图像网格
- ImageReview默认result=False vs TextReview默认result=None(不一致)

### 3.3 阶段三: 人工审核具体审核

**业务流程:**
```
[Reviewer] 审阅页面 → 查看任务列表 → 点击操作按钮 → 进入审核页面 → 按指标审核 → 提交审核结果
```

**页面:**
- 列表页: 前端用户端 `pages/review.vue`
- 审核页: 前端用户端 `pages/task/detail/[manual_review_id].vue`

**后端API:**
- `GET /get_reviewer_tasks/` → 审核员任务列表
- `GET /get_review_detail/<manual_review_id>/` → 审核详情
- `POST /post_review/<manual_review_id>/` → 提交审核结果

**审核模式判定:**
```javascript
if (imgs.length > 0 && texts.length > 0) → 'multi'
else if (imgs.length > 0) → 'image'
else if (texts.length > 0) → 'text'
```
paper_text和review_text都被归为'text'模式，通过ai_detection字段区分。

## 四、各材料类型的审核指标和方式

### 4.1 图像审核(image)

**审核界面:** 三栏布局(图像列表 | 图像预览+标注 | 维度评分)

**审核指标(7维度):**
| 维度 | 评分(1-5) | 理由(文本) | 标注(绘图) |
|------|----------|-----------|-----------|
| 高斯模糊 | ✓ | ✓ | ✓ |
| 亮度/对比度调节 | ✓ | ✓ | ✓ |
| 智能修复 | ✓ | ✓ | ✓ |
| 暴力覆盖 | ✓ | ✓ | ✓ |
| 同图复制 | ✓ | ✓ | ✓ |
| 重叠切割 | ✓ | ✓ | ✓ |
| 跨图拼接 | ✓ | ✓ | ✓ |

**最终判定:** 造假(true) / 真实(false)
**数据结构:** ImageReview模型 - 7个score + 7个reason + 7个points(JSON坐标) + result

### 4.2 论文文本审核(paper_text)

**审核界面:** 三栏布局(文本列表 | 文本内容+AI检测+审核表单 | 进度+提交)

**审核指标:**
| 指标 | 输入方式 | 说明 |
|------|---------|------|
| 段落复核 | 每段: 同意AI/不同意AI + 评论 | 逐段验证AI标记的生成段落 |
| 综合审核意见 | 文本域 | 对整篇论文的整体评价 |
| 最终判定 | 造假/真实 | 综合判定 |

**AI辅助:** 显示每段落的AIGC概率、事实性造假分析
**数据结构:** TextReview模型 - paragraph_reviews(JSON) + overall_comment + result

### 4.3 审稿文本审核(review_text)

**审核界面:** 同论文文本布局，但审核指标不同

**审核指标:**
| 指标 | 输入方式 | 说明 |
|------|---------|------|
| 模板化倾向评分 | 滑块(0-100) | 评估审稿文本的模板化程度 |
| 模板化倾向评论 | 文本域 | 对模板化倾向的具体分析 |
| 段落复核 | 每段: 同意AI/不同意AI + 评论 | 逐段验证(如存在AI标记) |
| 综合审核意见 | 文本域 | 对整篇审稿意见的整体评价 |
| 最终判定 | 造假/真实 | 综合判定 |

**AI辅助:** 显示template_tendency_score进度条、template_analysis_reason
**数据结构:** TextReview模型 - template_review_score + template_review_comment + paragraph_reviews + overall_comment + result

### 4.4 综合材料审核(multi_material)

**审核界面:** 标签页切换(图像审核 | 文本审核)，复用image和text的审核界面

**审核指标:** 合并图像和文本的全部指标
- 图像标签页: 同image的7维度评分+标注
- 文本标签页: 论文段落复核 + 审稿模板倾向评估 + 综合意见

**数据结构:** 同时提交ImageReview和TextReview数据

## 五、关键模型关系

```
DetectionTask ──┬── ImageUpload ──── DetectionResult ──── SubDetectionResult(×7)
                ├── ReviewTextResource ── TextDetectionResult
                └── StructuredDetectionResult (整体分析)

ReviewRequest ──┬── imgs(M2M ImageUpload)
                ├── text_resources(M2M ReviewTextResource)
                ├── reviewers(M2M User)
                ├── status1(pending→in_progress→completed)  # 发布者可见
                └── status2(pending→refused/accepted)        # 管理员可见

ManualReview ───┬── review_request(FK ReviewRequest)
                ├── reviewer(FK User)
                ├── imgs(M2M ImageUpload)
                ├── img_reviews(M2M ImageReview)
                ├── text_resources(M2M ReviewTextResource)
                └── status(undo→completed)

ImageReview ────┬── manual_review(FK ManualReview)
                ├── image(FK ImageUpload)
                ├── 7×score + 7×reason + 7×points(JSON)
                └── result(Boolean)

TextReview ─────┬── manual_review(FK ManualReview)
                ├── text_resource(FK ReviewTextResource)
                ├── paragraph_reviews(JSON)
                ├── template_review_score(Float)
                ├── template_review_comment(Text)
                ├── overall_comment(Text)
                └── result(Boolean)
```

## 六、已发现的问题清单

### 后端问题
1. **分页-过滤顺序错误**: `get_reviewer_manual_request`先分页后过滤，导致总数不匹配
2. **request.POST vs request.data**: `PostReportView`使用request.POST无法接收JSON
3. **重复赋值**: `get_review_detail`中'reviewers_results'键被赋值两次
4. **默认值不一致**: ImageReview默认result=False, TextReview默认result=None
5. **缺少数据库事务**: `post_review`无transaction.atomic包装
6. **重复辅助函数**: `_safe_avatar_url`在views_review和views_admin中重复定义

### 前端问题
7. **任务类型标签不一致**: history.vue("论文文本"/"Review文本") vs review.vue("论文检测"/"评审检测")
8. **颜色方案不一致**: history用主题色(primary/success/warning) vs review用字面色(blue/green/orange)
9. **审核提交payload不一致**: image用image_ids, text用task_id; image无reason
10. **列名拼写错误**: review.vue中'maual_review_time'应为'manual_review_time'
11. **组件未导入**: history.vue引用task-detail但未import
12. **管理端内联渲染**: reviews.vue未复用detection组件
13. **paper_text/review_text不区分**: 审核页面通过字段探测区分，不是显式类型标识
