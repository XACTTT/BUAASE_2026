## 分析结论

### 1. 预处理流程

PDF文件 → PyMuPDF (fitz) 按页提取文本块 → 每个文本块成为一个 section
- section 命名规则：`"第{page+1}页-段落{block_idx+1}"`
- 每个 section 有唯一 ID：`paper_paper_{file_idx}_{section_idx}`（如 `paper_paper_0_0`）

TXT → 双换行分割段落
DOCX → XML 段落解析
DOC → 原始文本 + 双换行分割

### 2. 提交给模型

所有 section 作为 ONE batch 一起提交给 BERT AI 服务（bert_text_ai_bridge.py）
- 一次 SSH/SCP 请求发送所有 text items
- BERT 模型（QiDeBERTa）对每个 section 做二分类（人/AI）

同时，structured 管线（trigger_structured.py）对拼接后的全文做规则+ML分析：
- 4个维度：学术不端(0.35)、AIGC生成(0.30)、文本篡改(0.20)、数据图表伪造(0.15)
- 使用规则打分 + TF-IDF/LogisticRegression + IsolationForest

### 3. 结果

**BERT 返回两层结果：**
- per_section: 每个 section 的 is_aigc、confidence_score、probabilities
- aggregate: aigc_ratio、mean_confidence 等

**后端聚合后存储在 StructuredDetectionResult.result_payload JSON 字段中：**
```json
{
  "overall": { "is_fake": true, "risk_level": "high", "confidence_score": 0.78 },
  "per_section": [
    { "section_id": "paper_paper_0_0", "is_aigc": true, "confidence": 0.87 },
    ...
  ],
  "dimensions": { ... },
  "evidence": { ... }
}
```

### 4. 用户的理解是否正确

**基本正确，但有一个重要细节：**

- 材料确实是拆分后一起提交给模型 ✓
- 但模型返回的不是一个"整块"结果，而是**每个 section 都有独立的检测结果** + 一个聚合结果 ✓
- **拆分后的材料没有保存在 media 中** ✗ — 只存在于内存中，随请求结束而消失
- 但 `result_payload.per_section` 中包含了每个 section 的文本预览(`text_preview`)和检测结果

### 5. 当前前端显示方式

- `TextDetectionResultView.vue`：水平滚动卡片列表，每张卡片是一个段落
- 没有"点击选择 → 右侧详情"的交互模式
- 与图像检测的 `DetectionReviewStep.vue`（网格选择 + Tab 详情）风格不一致

## 改造方案

用户已确认，开始执行。改造分为后端和前端两部分。

---

### 后端改造：`structured_detection_service.py`

**目标**：在 `per_section` 中保存每个段落的完整文本内容，而非仅存检测结果。

**改动**：
1. `_aggregate_bert_batch` 方法签名增加 `text_items` 参数
2. 构建 `text_lookup` 字典：`item['id']` → `item`（包含 `text` 字段）
3. 构建 `section_meta` 字典：从 snapshot 的 paper_files 中提取 `title`、`page_number`、`source_file`
4. 每个 `per_section` 条目新增 4 个字段：`text`、`title`、`page_number`、`source_file`

**改动后 per_section 单条数据结构**：
```json
{
  "item_id": "paper_paper_0_0",
  "is_aigc": true,
  "label_name": "AIGC",
  "confidence_score": 0.87,
  "probabilities": { "human": 0.13, "aigc": 0.87 },
  "text": "完整的段落文本内容...",
  "title": "第1页-段落1",
  "page_number": 1,
  "source_file": "example.pdf"
}
```

---

### 前端改造：`TextDetectionResultView.vue`

**目标**：仿照图像检测页面（DetectionReviewStep.vue），改为左侧段落列表 + 右侧详情面板的交互模式。

**改动**：
1. 新增 `SectionItem` 接口（9 个字段，与后端 per_section 一一对应）
2. 新增 `structuredSections` computed，从 `taskMeta.result.evidence.per_section` 读取数据
3. 用 `item_id.includes('_paper_')` 过滤出论文段落（排除 review 段落）
4. 新增 `selectedSectionIndex`、`selectedSection`、`selectSection()` 实现选择交互
5. 论文文本检测区域重写为两栏布局：
   - 左栏（md=4）：可滚动的段落列表，每项显示标题、风险等级色标、置信度进度条，点击选中
   - 右栏（md=8）：选中段落的详情面板，包含段落信息卡片、BERT检测结果卡片（置信度+概率分布）、文本内容卡片
6. 未选中时显示占位提示

### 验证结果

| 检查项 | 结果 |
|--------|------|
| 前后端字段名匹配（9/9） | 一致 |
| 数据类型匹配 | 一致 |
| `taskMeta.result.evidence.per_section` 路径 | 正确 |
| `item_id.includes('_paper_')` 过滤器 | 正确匹配 `paper_paper_0_0` 等 ID |
| `probabilities.human` / `probabilities.aigc` 键名 | 一致 |

数据链路：`result_payload`（数据库）→ API 响应的 `result` 键 → 前端 `taskMeta.result.evidence.per_section`
