# 前端部署说明

## 服务器分布

| 角色 | IP | 说明 |
|------|-----|------|
| 后端 API | `82.156.232.106` | Django + uwsgi，处理 /api/ 和 /ws/ |
| 前端 | `116.63.14.7` | nginx 静态文件服务 |

## 前端访问地址

| 应用 | 端口 | 地址 | 服务器目录 |
|------|------|------|-----------|
| 前端用户端 | 8090 | `http://116.63.14.7:8090` | `/data/vue-project/` |
| 前端管理端 | 8091 | `http://116.63.14.7:8091` | `/data/vue-project2/` |

## 架构

```
浏览器 ──→ 116.63.14.7:8090  用户端 (静态文件)
浏览器 ──→ 116.63.14.7:8091  管理端 (静态文件)
浏览器 ──→ 82.156.232.106/api/...  HTTP API (前端 JS 直连)
浏览器 ──→ 82.156.232.106/ws/...   WebSocket (前端 JS 直连)
```

两个前端构建时 `VITE_API_URL=http://82.156.232.106`，所以 JS 直接跨域请求后端（后端已配置 `CORS_ALLOW_ALL_ORIGINS = True`）。

## 116.63.14.7 nginx 配置

nginx 配置文件在 `/etc/nginx/conf.d/frontends.conf`：

```nginx
server {
    listen 8090;
    root /data/vue-project/;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
}

server {
    listen 8091;
    root /data/vue-project2/;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
}
```

**注意：** 服务器原有 nginx 配置（`/etc/nginx/nginx.conf` 中 80 端口代理到 uwsgi）不能动，是其他后端在用。

## 更新部署流程

本地操作：

```bash
# 1. 修改 .env 中 VITE_API_URL（如需）
# 2. 构建
cd AI学术鉴伪/代码/前端/前端用户端 && npm run build
cd AI学术鉴伪/代码/前端/前端管理端 && npm run build

# 3. 上传（用 tar 管道，scp 有 Windows 路径问题）
cd AI学术鉴伪/代码/前端/前端用户端/dist && tar czf - . | ssh root@116.63.14.7 "tar xzf - -C /data/vue-project/"
cd AI学术鉴伪/代码/前端/前端管理端/dist && tar czf - . | ssh root@116.63.14.7 "tar xzf - -C /data/vue-project2/"

# 4. nginx 无需重启（静态文件直接替换生效）
# 如需清除浏览器缓存，强制刷新即可
```

## 关键配置位置

| 文件 | 作用 |
|------|------|
| `前端用户端/.env` | `VITE_API_URL` — 构建时注入的 API 地址 |
| `前端管理端/.env` | 同上 |
| `前端用户端/src/api/websocket.ts` | WebSocket 地址（由 VITE_API_URL 推导） |
| `前端用户端/src/pages/history.vue` | 任务 WebSocket 地址（同上） |
| `前端用户端/src/pages/review.vue` | 头像 URL（同上） |

## 注意事项

- WebSocket 和头像 URL 之前硬编码为旧 IP `122.9.45.122`，已改为从 `VITE_API_URL` 动态推导
- 用户端和管理端使用不同的 token 存储 key（`2-token` / `1-token`），互不影响
- 80 端口被服务器其他后端占用，前端用 8090/8091
